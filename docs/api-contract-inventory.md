# AL-LMS frontend API contract inventory

## Scope and evidence

Reviewed frontend source under `src/` at the current `refactor/al-02a-api-contract-inventory` checkout, legacy `quranBack/main.py` plus imported `User/` and `Course/` modules, the modular `quranBack/app/` registry and routes, and the AdminJS application configuration. Backend and admin inspection was read-only. This records source-level contracts; no API, SMS, payment, or authentication request was sent.

The frontend has no central API wrapper for application requests. Most imports use Axios directly. `src/index.js` imports `src/api/axios.js`, setting Axios’ global base URL to `https://api.srvschool.ir/`; paths below are relative to that base unless stated otherwise. A smaller legacy surface passes `baseURL: getUrl() + "back_request/..."`, where `getUrl()` uses the current page origin except on localhost (then `https://daarolquran.com/`). Calls to `api.srvschool.ir` use paths such as `/authen/user`; this origin/path distinction is material. Requests to a literal external host are stated separately.

Authentication is inconsistent: many screens send `Authorization: Bearer <token>` read from local storage, some use form or cookie credentials, and public catalog calls omit auth. `axiosPrivate` can attach the in-memory access token and retry after 403, but the inspected feature calls predominantly import bare `axios`; the hook does not globally secure those calls. The response interceptor reloads on 401. Successful legacy responses are commonly read as `{tracking_code, response, error}`; Axios REST pages commonly expect arrays/objects directly from `response.data`. Contracts are inferred only from caller code and are marked accordingly.

## Cross-cutting contract observations

### Direct Axios URL literals

Static scan found **42 distinct relative URL literals** used as Axios method arguments or `url` config values (including one dynamically interpolated search URL). This count excludes the generic legacy `/back_request/*` routes, path-variable file URLs, external absolute URLs, and commented-out examples. Grouped list:

- Auth/profile: `/authen/user`, `/authen/update_profile/`, `/authen/change_password/`, `/authen/user_ip/`, `/refresh`
- Course: `/course/courseStudent/`, `/course/coursehw/`, `/course/coursehwAns/`, `/course/specificstudentCourse/`, `/course/teacherCourse/`
- Dashboard and wallet: `/dashboard/search`, `/dashboard/basket`, `/dashboard/discount`, `/dashboard/userdiscount`, `/dashboard/wallet`
- Archive: `/archive/archiveFiles/`, `/archive/archiveOfflineHeader/`
- Forum: `/forum/forumDetail/`, `/forum/forumHeader/`
- Live: `/live/getmeetings`, `/live/join/`, `/live/student_join/`
- Notifications: `/notification/student/`
- Packages: `/package/normalPackage`, `/package/normalPackageCourse`, `/package/studentPackage`, `/package/studentPackageCourse`, `/package/timingPackage`, `/package/timingPackageCourse`
- Quizzes: `/quiz/quizHeader/`, `/quiz/quizQuestion/`, `/quiz/studentQueez/`, `/quiz/studentres/`, `/quiz/totalqH/`, `/quiz/totalqQ/`, `/quiz/totalqSu/`, `/quiz/tstudentres/`
- Sliders: `/slider/`, `/slider/banner`
- Payments: `/zarinpal/buybasket/`, `/zarinpal/buywallet/`, `/zarinpal/report/`

The generic legacy URL templates additionally used are `POST /back_request/token/`, `POST /back_request/register/`, `POST /back_request/select_request/`, `POST /back_request/insert_request/`, and `POST /back_request/update_request/`. These are four generic dispatch routes plus the dedicated token route (five distinct URL templates); the action labels are documented in the corresponding table row. Explicit legacy file routes used as browser links contribute six additional filename templates. Thus the audited inventory covers **54 distinct backend/external endpoint templates** when counting 42 Axios relative paths, five generic legacy routes, six file routes, and the external IP lookup; media host URLs and the meeting room page are asset/navigation links and excluded from this endpoint total.

- The active UI has at least two API origins: `api.srvschool.ir` for shared Axios calls and the page-origin-derived `back_request` origin for legacy calls. `localhost` deliberately falls back to the production site origin. This makes local development and environment migration surprising.
- Error contracts differ: legacy calls inspect `tracking_code` and `error`; REST-like calls generally use raw `response.data`; Axios’ global 401 interceptor reloads the page. Some calls do not catch network errors, and `error.response.status` can itself throw when no response exists.
- The auth hook’s 403 refresh flow applies only to `axiosPrivate`, whereas feature calls mostly import the default Axios singleton. `useRefreshToken` requests `GET /refresh` with cookies, but no matching handler was found in the inspected backend.
- `src/pages/dashboard/students/quiz/StartQuiz.js` constructs `quiz/quizHeader/?c_id=${id}}` with an extra closing brace; treat this as a source-level likely URL defect, not a proven server incompatibility.
- Download links and images bypass the Axios request layer, so they do not automatically attach bearer headers.
- The legacy and new FastAPI applications are distinct app objects: deployment documentation says deployed service remains `uvicorn main:app`, while modular foundation is `uvicorn app.main:app`.

## Migration recommendations

1. Capture these existing calls as request/response fixtures from a safe staging environment before changing behavior; the source alone cannot establish all response schemas.
2. Define one typed API client per actual service origin, with environment configuration and explicit auth/cookie policy. Preserve legacy envelope actions behind a compatibility adapter during migration.
3. Prioritize authentication, OTP, payment callback/reporting, file authorization, and user/course ownership checks. Document token storage and refresh semantics before replacing auth.
4. Move endpoint schemas and ownership to backend OpenAPI or versioned contract artifacts; compare frontend consumers against those artifacts in CI.
5. Retire dead WebSocket/PeerJS demo code or formally connect the live-class flow to its owning service; do not infer the meeting transport from the page URL.
